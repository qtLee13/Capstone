## 1. Shortcut Learning — ทำไมโมเดลถึงจับ `X wrote:` แทนเนื้อหา

**Geirhos, R., Jacobsen, J.-H., Michaelis, C., Zemel, R., Brendel, W., Bethge, M., Wichmann, F. A.**
*Shortcut learning in deep neural networks.*
**Nature Machine Intelligence**, vol. 2, pp. 665–673 (2020) · DOI: `10.1038/s42256-020-00257-z`

### ใจความ

> Shortcut คือกฎการตัดสินใจที่ **ทำได้ดีบนชุดทดสอบมาตรฐาน แต่ล้มเหลวเมื่อเจอเงื่อนไขที่ท้าทายกว่า
> เช่นสถานการณ์จริง** และความล้มเหลวหลาย ๆ อย่างของ deep learning เป็นอาการของปัญหาเดียวกันนี้

### ตรงกับที่เราวัดได้เป๊ะ

| สิ่งที่ paper บอก | สิ่งที่เราวัดได้ (26 ส.ค. 2026) |
|---|---|
| โมเดลหาสัญญาณที่ทำนาย label ได้ง่ายที่สุด | สแปม 1,898 ฉบับ **ไม่มี `X wrote:` เลยสักฉบับ** · ham มี 31% → ทำนายได้เกือบสมบูรณ์ |
| ทำได้ดีบนชุดทดสอบมาตรฐาน | held-out ให้ 99.4% |
| ล้มเหลวกับข้อมูลจริง | FP จริง 25.2% (ต่างกัน 180 เท่า) |
| ชุดทดสอบมีทางลัดเดียวกับชุดเทรน | `english_holdout.csv` เอียงเรื่องความยาวแบบเดียวกับชุดเทรน |

### ประโยคที่ใช้ตอบได้

> *"สิ่งที่เราเจอเรียกว่า shortcut learning ตาม Geirhos et al. (Nature Machine Intelligence 2020)
> โมเดลไม่ได้ทำงานผิด มันหาสัญญาณที่ทำนาย label ได้ถูกที่สุดในข้อมูลที่เราป้อนให้
> ปัญหาอยู่ที่ชุดข้อมูล ไม่ใช่ที่สถาปัตยกรรมโมเดล"*

**อ้างอิง**
- [Nature Machine Intelligence](https://www.nature.com/articles/s42256-020-00257-z)
- [โค้ดประกอบ paper — GitHub](https://github.com/rgeirhos/shortcut-perspective)

## 2. Base-Rate Fallacy — ทำไม FP 25% ถึงทำให้ระบบใช้ไม่ได้

**Axelsson, S.** *The base-rate fallacy and the difficulty of intrusion detection.*
**ACM Transactions on Information and System Security (TISSEC)**, vol. 3, no. 3, August 2000
(ฉบับก่อนหน้าอยู่ใน Proceedings of the 6th ACM CCS, 1999, pp. 1–7)

### ใจความ

ปัญหาเกิดเมื่อ **อัตราการแจ้งเตือนผิดสูง มาเจอกับความน่าจะเป็นที่จะถูกโจมตีจริงที่ต่ำ**
ผลคือการแจ้งเตือนส่วนใหญ่เป็นของปลอม แม้ตัวตรวจจับจะดู "แม่น" ก็ตาม
และ Axelsson เตือนว่าปัญหานี้จะ **แย่ลง** เมื่อปริมาณข้อมูลโตขึ้นเร็วกว่าการโจมตี

### ทำไมสำคัญกับรายงานของเรา

ถ้าอาจารย์ถามว่า *"FP 25% แต่จับสแปมได้ 97.5% ก็ดูดีแล้วไม่ใช่หรือ"* —
นี่คือคำตอบที่มีชื่อเรียกและมีงานอ้างอิง:

> เมลปกติมีมากกว่าเมลอันตรายหลายเท่าในองค์กรจริง
> FP 25% บนฐานที่ใหญ่กว่ามาก ทำให้ **จำนวนสัมบูรณ์** ของการแจ้งเตือนผิด
> ท่วมการแจ้งเตือนที่ถูก จนคนเลิกเชื่อระบบ

เชื่อมกับ Ho et al. 2017 ใน [03](03_related_work.md) ที่ตั้งเป้าหมายเป็น
"จำนวนการแจ้งเตือนต่อวันที่คนตรวจไหว" แทนที่จะเป็นเปอร์เซ็นต์ความแม่น

**อ้างอิง**
- [ACM TISSEC (2000)](https://dl.acm.org/doi/10.1145/357830.357849)
- [ACM CCS (1999)](https://dl.acm.org/doi/10.1145/319709.319710)

## 3. บทเรียนที่เรายืนยันเองแล้ว (ไม่มี paper แต่มีข้อมูล)

รายการนี้เป็นของโครงการเรา วัดเอง ไม่ได้อ้างใคร แต่ **มีตัวเลขรองรับทุกข้อ**

| บทเรียน | หลักฐาน |
|---|---|
| ชุดวัดที่มีอคติแบบเดียวกับชุดเทรน ให้ตัวเลขที่ไม่มีความหมาย | held-out 99.4% vs ของจริง 74.8% |
| การขยับ threshold แก้ shortcut ไม่ได้ | FP กระจุกที่ 99–100 · ขยับ 50→90 ตัดได้แค่ 88/1,046 (8%) |
| ทางลัดกลายเป็นช่องโหว่ด้านความปลอดภัยทันที | เติม 1 บรรทัด สแปมที่จับได้ 100% หลุดไป 43.5% |
| การ "แก้ที่ตอนใช้งาน" ทำให้แย่ลง | ถ้าลบ `wrote:` ออกตอน preprocess เมลปกติทั้งหมดจะไปอยู่กลุ่มที่ FP 34.5% |
| ต้องพิสูจน์เชิงสาเหตุ ไม่ใช่แค่ correlation | ทดสอบเติม/ลบบนเมลฉบับเดิม + ตัวคุมตัวแปร (`Hello,` ขยับ < 0.2 จุด) |

รายละเอียดทั้งหมดอยู่ใน [`stage1_wrote_shortcut.json`](../stage1_wrote_shortcut.json)
