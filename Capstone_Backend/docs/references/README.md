# เอกสารอ้างอิง — สมการคำนวณของ Stage 2 มาจากไหน

> จัดทำ 2026-08-26 เพื่อเตรียมตอบคำถามอาจารย์
> ทุกรายการในโฟลเดอร์นี้ตรวจสอบ URL แล้วว่ามีอยู่จริง ณ วันที่จัดทำ

---

## ⚠️ อ่านตรงนี้ก่อน — คำตอบที่ซื่อสัตย์ที่สุด

ถ้าอาจารย์ถามว่า **"ตัวเลข 45 กับ 40 ในตารางน้ำหนักมาจากงานวิจัยไหน"**
คำตอบคือ **ไม่ได้มาจากงานวิจัยหรือบริษัทไหนเลย — เราตั้งเองจากอัตราการติดที่เราวัดเอง**

การอ้างว่า "มาจาก paper X" ทั้งที่ไม่ใช่ จะเสียหายกว่าการตอบตรง ๆ มาก
และถ้าอาจารย์ขอดู paper ที่อ้าง แล้วเปิดไปไม่เจอตัวเลขนั้น จะกู้กลับยาก

**สิ่งที่มีอ้างอิงจริงคือ "วิธีการ" ไม่ใช่ "ตัวเลข"** แยกให้ชัดตามตารางข้างล่าง

---

## ตารางแยก: อะไรมีอ้างอิง อะไรเป็นของเราเอง

| สิ่งที่เราทำ | สถานะ | อ้างอิง |
|---|---|---|
| ให้คะแนนแบบ **รวมน้ำหนักของกฎหลายข้อ แล้วเทียบกับเกณฑ์** | ✅ มีแบบอย่างในระบบที่ใช้งานจริงระดับโลก | SpamAssassin · Microsoft Defender → [01](01_scoring_method.md) |
| ตั้งน้ำหนักด้วยมือก่อน แล้วค่อยหาค่าจริงจากข้อมูลทีหลัง | ✅ เป็นเส้นทางเดียวกับที่ SpamAssassin เดินมา | [01](01_scoring_method.md) |
| แบ่งประเภทเป็น Phishing / BEC / Malware / Spam | ✅ ตรงกับการจัดหมวดของ MITRE ATT&CK | [02](02_attack_taxonomy.md) |
| ใช้สัญญาณ "การปลอมตัวผู้ส่ง" เป็นตัวชี้ BEC | ✅ ตรงกับงานวิจัยที่ใช้ในผลิตภัณฑ์จริง | Cidon et al. 2019 → [03](03_related_work.md) |
| ใช้ logistic regression เพื่อให้อธิบายที่มาของคะแนนได้ | ✅ เหตุผลเชิงวิชาการรองรับ | [03](03_related_work.md) |
| อธิบายว่าทำไม FP 25% ถึงเป็นเรื่องใหญ่ | ✅ base-rate fallacy | Axelsson 2000 → [04](04_model_pitfalls.md) |
| อธิบายว่าทำไมโมเดลถึงจับ `X wrote:` แทนเนื้อหา | ✅ shortcut learning | Geirhos et al. 2020 → [04](04_model_pitfalls.md) |
| ใช้ Wilson score interval รายงานช่วงความเชื่อมั่น | ✅ เป็นวิธีที่แนะนำในวรรณกรรมสถิติ | Brown et al. 2001 → [05](05_statistics.md) |
| **ค่าน้ำหนักแต่ละตัว (45, 40, 35, −40 …)** | ❌ **ของเราเอง** | ตั้งจากอัตราการติดที่วัดบน phishing_pot 8,612 ฉบับ |
| **เกณฑ์ `ATTACK_TYPE_MIN_SCORE = 35`** | ❌ **ของเราเอง** | ตั้งจากการสังเกตว่าที่ 25 สัญญาณอ่อนตัวเดียวตัดสินได้ |
| **เกณฑ์ความมั่นใจ (60/30 · 40/15)** | ❌ **ของเราเอง** | ยังไม่ได้ปรับจากข้อมูล |
| **รายการหลักฐาน 20 ตัว** | 🟡 ผสม | ตัวที่มาจาก SPF/DKIM/DMARC มี RFC รองรับ ที่เหลือเราออกแบบเอง |

## สคริปต์ที่จะเปลี่ยน ❌ ให้เป็น ✅

[`scripts/fit_attack_type_equation.py`](../../scripts/fit_attack_type_equation.py)
ใช้ logistic regression หาค่าน้ำหนักจาก label ที่ **คนตัดสินจริง** แทนที่จะตั้งเอง
ผลที่ได้จะเป็นค่าสัมประสิทธิ์ + odds ratio ซึ่งตอบได้ว่า
*"ถ้ามีการปลอมชื่อองค์กร โอกาสเป็น BEC เพิ่มขึ้นกี่เท่า"*

**ติดอยู่ที่:** ยังไม่มีใครกรอก `type_label_worksheet.xlsx` (400 แถว) ต้องการอย่างน้อย 25 ตัวอย่างต่อประเภท

## ประโยคที่ใช้ตอบอาจารย์ได้เลย

> *"วิธีการให้คะแนนของเราใช้แนวเดียวกับ SpamAssassin คือรวมน้ำหนักของกฎหลายข้อแล้วเทียบกับเกณฑ์
> ซึ่งเป็นวิธีที่ระบบกรองอีเมลที่ใช้งานจริงใช้กันมานาน
>
> แต่ **ค่าน้ำหนักตอนนี้เราตั้งเองจากอัตราการติดที่วัดได้ ยังไม่ได้ฟิตจากข้อมูลที่คนติดป้าย**
> ซึ่งเป็นขั้นเดียวกับที่ SpamAssassin เคยผ่านมา — เวอร์ชันแรกตั้งด้วยมือ แล้วค่อยเปลี่ยนไปใช้
> genetic algorithm และ perceptron หาค่าจากคลังจดหมายจริง
>
> ขั้นต่อไปของเราคือใช้ logistic regression ทำแบบเดียวกัน เพื่อให้ตอบเป็น odds ratio ได้"*
