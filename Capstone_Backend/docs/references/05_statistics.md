## Wilson Score Interval — ช่วงความเชื่อมั่นที่เราใช้ทุกที่

**Brown, L. D., Cai, T. T., DasGupta, A.** *Interval Estimation for a Binomial Proportion.*
**Statistical Science**, vol. 16, no. 2, pp. 101–133 (2001) · DOI: `10.1214/ss/1009213286`

### ใจความของ paper

- ช่วงความเชื่อมั่นแบบ **Wald** (ที่สอนกันทั่วไป คือ `p ± 1.96·√(p(1−p)/n)`) มีพฤติกรรม **แปรปรวนผิดปกติ**
- ผู้เขียนระบุว่าคำแนะนำในตำราเรื่องความปลอดภัยของ Wald นั้น **"ชวนให้เข้าใจผิดและบกพร่อง"**
- **แนะนำให้ใช้ Wilson interval** (หรือ Jeffreys prior แบบ equal-tailed) สำหรับ n น้อย
  และ Agresti–Coull สำหรับ n ใหญ่

### ทำไมเราถึงต้องใช้ Wilson จริง ๆ ไม่ใช่แค่ทำตามตำรา

หลายตัวเลขในรายงานของเราอยู่ที่ **ขอบ 0% หรือ 100%** ซึ่งเป็นจุดที่ Wald พังชัดที่สุด:

| ผลที่เราวัด | ถ้าใช้ Wald |
|---|---|
| ham 0–250 ตัวอักษรที่มี `wrote:` → FP **0/22 = 0%** | ได้ช่วง `0 ± 0` = "มั่นใจ 100% ว่าเป็น 0" ซึ่งผิดชัด ๆ |
| สแปมก่อนเติมบรรทัด → จับได้ **400/400 = 100%** | ได้ `[100%, 100%]` เช่นกัน |
| Wilson ให้ | `[0.0%, 14.9%]` และ `[99.0%, 100%]` ตามลำดับ — สะท้อนว่า n น้อยแปลว่ายังไม่แน่ |

> ประโยคที่ใช้ตอบได้: *"เราใช้ Wilson score interval เพราะหลายค่าที่วัดได้อยู่ที่ขอบ 0 หรือ 100%
> ซึ่งเป็นจุดที่ช่วงความเชื่อมั่นแบบ Wald ให้ผลผิด — ตามที่ Brown, Cai และ DasGupta (2001) ชี้ไว้"*

### สูตรที่เราเขียนในโค้ด

พบใน `eval_*.py` ทุกไฟล์ และ `scripts/` — เขียนเหมือนกันทุกที่:

```python
z, p = 1.96, k / n
d = 1 + z*z/n
c = p + z*z/(2*n)
m = z * math.sqrt(p*(1-p)/n + z*z/(4*n*n))
lower, upper = (c - m)/d, (c + m)/d
```

## Logistic Regression และ Odds Ratio

ใช้ใน [`scripts/fit_attack_type_equation.py`](../../scripts/fit_attack_type_equation.py)

### สมการ

$$\text{logit}(T) = b_0 + b_1 x_1 + b_2 x_2 + \dots + b_n x_n$$

$$P(T) = \frac{1}{1 + e^{-\text{logit}(T)}}$$

### ทำไมต้องรายงาน odds ratio ด้วย

ค่าสัมประสิทธิ์ $b_i$ อยู่ในหน่วย log-odds ซึ่งอ่านเป็นภาษาคนไม่ได้
แปลงเป็น **odds ratio** ด้วย $e^{b_i}$ แล้วอ่านได้ทันที:

> *"ถ้าพบ `spoof_own_org` โอกาส (odds) ที่จะเป็น BEC เพิ่มขึ้น N เท่า
> เมื่อควบคุมตัวแปรอื่นให้คงที่"*

นี่คือรูปคำตอบที่อาจารย์น่าจะอยากได้ตอนถามว่า *"ได้ตัวเลขนี้มายังไง"*

### วิธีที่ตั้งใจกันข้อผิดพลาดไว้ในสคริปต์

| การป้องกัน | เหตุผล |
|---|---|
| `class_weight="balanced"` | จำนวนตัวอย่างแต่ละประเภทไม่เท่ากันแน่นอน |
| `log1p` กับตัวแปรที่เป็นจำนวน แล้ว standardize | ไม่งั้น `link_count` จะครอบงำค่าสัมประสิทธิ์เพราะสเกลใหญ่กว่า |
| **fit ด้วยชุด A+B แต่รายงานผลด้วยชุด A เท่านั้น** | ชุด B ถูกคัดมาให้แยกง่ายโดยตั้งใจ ถ้าเอามารายงานตัวเลขจะสวยเกินจริง |
| `MIN_PER_CLASS = 25` | ต่ำกว่านี้ค่าสัมประสิทธิ์ไม่มีความหมาย |
| ตัด `link_text_mismatch` / `attachment_risk` ออกจาก feature | ชุดข้อมูลที่ใช้ fit คำนวณสองตัวนี้ไม่ได้ → ใส่เข้าไปจะเป็น train/serving skew |
