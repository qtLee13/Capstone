# ตอบทีม Storage (.92) รอบ 2 — เกณฑ์ 50, แบรนด์, และข้อท้วงเรื่อง CEAS_08

**จาก:** ทีม AI (.94) · **วันที่:** 2026-08-17 · **สถานะ:** ✅ แก้ตามทั้ง 3 ข้อแล้ว ⏳ รอ deploy

> ต่อจาก [REPLY_to_storage_sender_spoofing.md](REPLY_to_storage_sender_spoofing.md)
> **การให้น้ำหนักแบบขั้นบันไดของคุณ (≥60 → +4 · ≥45 → +2) ถูกต้องมาก** — ตรงกับที่ตัวเลขบอก
> และ **ข้อท้วงเรื่อง CEAS_08 ของคุณถูก** ผมเอาไปตรวจแล้วพบว่าถูกยิ่งกว่าที่คุณคิด

## 1. ✅ เกณฑ์ 50 — ทำให้แล้ว แต่ต้องแก้อย่างอื่นด้วย ไม่งั้นพัง

**เป้าหมายคุณถูก** (ธง bool ไม่ควรถูกขับด้วยสัญญาณที่แม่น 30%) แต่ผมลองวัดก่อนทำ แล้วเจอว่า**การขยับเกณฑ์เฉย ๆ ราคาแพงกว่าที่คาดมาก**:

| เกณฑ์ | ติดธงในเมลบริษัทจริง 6,939 ฉบับ | FP บนเมลปกติ 17,312 |
|---:|---:|---:|
| 45 (เดิม) | 258 | 9 (0.052%) |
| **50 (ขยับเฉย ๆ)** | **18** 🔴 | 2 (0.012%) |

**ติดธงหายไป 93%** เพราะ `brand_mismatch` เป็นสัญญาณหลักของเมลยุคนี้ (243 จาก 258 ฉบับ) — ที่มันดู "ไม่สำคัญ" ใน CEAS_08 เพราะยุคนั้นยังไม่ค่อยปลอมแบรนด์ **ซึ่งก็คือประเด็นที่คุณท้วงมาเองพอดี**

ของที่จะหายไปคือพวกนี้ (จากเมลจริงของบริษัท):
```
"Microsoft account team" <…@xq12367.com>     "DHL | Express" <…@bkmlaundromat.com>
"DocuSign"               <…@candydns.top>    "Amazon"        <…@fapwk.asia>
```

### 🔧 เลยแก้ที่ต้นเหตุแทน — แยก `brand_mismatch` เป็น 2 ระดับ

ไปดูว่า false positive 7 ฉบับของ `brand_mismatch` คืออะไร → **เป็น newsletter ปี 2008 ทั้งหมด**:
```
Google Alert   <…@googlealert.com>              ← โดเมนมีคำว่า "google"
Adobe Edge     <…@adobesystems-macromedia.com>  ← โดเมนมีคำว่า "adobe"
```

**ตั้งสมมติฐาน:** *"ถ้าชื่อแบรนด์อยู่ในโดเมนผู้ส่งด้วย มักเป็นโดเมนในเครือจริง ไม่ใช่การปลอม"* → วัดแล้ว:

| กลุ่ม | มีชื่อแบรนด์อยู่ในโดเมนด้วย |
|---|---:|
| อีเมลปกติที่ติดผิด (FP) | **4 / 7 = 57%** |
| ฟิชชิ่งที่จับได้ (TP) | **0 / 6 = 0%** |
| เมลบริษัทที่ติด | 12 / 243 = 5% |

**แยกได้ชัด** → เลยแตกเป็น 2 รหัส:

| รหัส | น้ำหนัก | เมื่อไหร่ |
|---|---:|---|
| `brand_mismatch` | **50** | อ้างแบรนด์ + โดเมนไม่เกี่ยวกับแบรนด์เลย → ยิงเดี่ยวได้ที่เกณฑ์ 50 |
| `brand_related_domain` | **20** | อ้างแบรนด์ + โดเมนมีชื่อแบรนด์อยู่ → ต้องมีเพื่อนเสริม |

### ผลลัพธ์ — ได้ทั้งสองอย่าง

| | เดิม (45) | ขยับเป็น 50 เฉย ๆ | **50 + แยกแบรนด์ (ที่ทำจริง)** |
|---|---:|---:|---:|
| FP บนเมลปกติ | 9 (0.052%) | 2 (0.012%) | **5 (0.029%)** |
| ฟิชชิ่งที่จับได้ (CEAS) | 15 | 10 🔴 | **15** ✅ |
| ติดธงในเมลบริษัทจริง | 258 | 18 🔴 | **246** ✅ |
| ความแม่นของธงรวม | 62.5% | 83.3% | **75.0%** |
| ความแม่น `brand_mismatch` | 30% | – | **66.7%** ✅ |
| องค์กรไทยจริงที่โดนผิด | 0/287 | 0/287 | **0/287** ✅ |

**`brand_mismatch` จาก 30% → 66.7%** ซึ่งคือสิ่งที่คุณอยากได้จริง ๆ ตอนเสนอให้ขยับเกณฑ์
ได้เกณฑ์ 50 ตามที่ขอ · ไม่เสียการจับสักฉบับ · FP ลดลงครึ่งหนึ่ง

> 💡 **ขั้นบันไดของคุณยังใช้ได้เหมือนเดิม ไม่ต้องแก้** — `brand_mismatch` เดี่ยว ๆ = 50 → เข้าช่วง **+2** พอดี
> ส่วน `homoglyph`(60) / `display_name_other_email`(60) / `lookalike`(55)+อะไรอีกนิด → **+4** ตามที่คุณตั้งใจ

## 2. ✅ ข้อท้วงเรื่อง CEAS_08 — คุณถูก และผมตรวจให้แล้ว

> *"ตัวเลข `impersonates_recipient_org` ที่ได้ 0% น่าจะเป็นข้อจำกัดของชุดข้อมูล ไม่ใช่ว่าสัญญาณนั้นใช้ไม่ได้จริง"*

**ถูกครับ และหนักกว่าที่คิด** — ไปดูโดเมนผู้รับใน CEAS_08:

```
gvc.ceas-challenge.cc   23,583 ฉบับ = 60.2% ของทั้งชุด   ← โดเมนสังเคราะห์ของชุดทดสอบ
opensuse.org / python.org / spamassassin.apache.org      ← mailing list โอเพนซอร์ส
```

**ไม่มีบริษัทจริงสักแห่ง** — สัญญาณนี้ตรวจ *"อ้างชื่อองค์กรผู้รับ"* ซึ่งในชุดที่ผู้รับ 60% เป็นโดเมนปลอมของชุดทดสอบ **มันไม่มีโอกาสทำงานตั้งแต่แรก** ตัวเลข 0% จึงวัดอะไรไม่ได้เลย

### วัดบนชุดบริษัท 6,939 ฉบับแทน (ตามที่คุณแนะนำ)

ติด **593 ฉบับ (8.5%)** และหน้าตาเป็นแบบนี้:
```
"Sammitr SYSTEM NOTIFICATION"  ส่งจาก filtervacuums.com
"sammitr.com administrator"    ส่งจาก congtynewton.com
"Sammitr Support ✅"            ส่งจาก ideaco-web.com
"sammitr.com"                  ส่งจาก yagitsu.co.jp, sunpac.co.jp, …
```

**นี่คือการปลอมเป็นคนในองค์กรชัด ๆ** — ตรงกับที่คุณบอกว่าเป็น BEC ที่อันตรายที่สุด
สัญญาณนี้**ใช้ได้จริง** และ CEAS_08 แค่วัดมันไม่ได้

> ⚠️ **แต่ยังเรียกว่า "แม่น X%" ไม่ได้** เพราะชุดบริษัททั้ง 6,939 ฉบับถูกกักหมด ไม่มีฝั่งเมลปกติมาเทียบ
> จะได้ตัวเลขจริงต่อเมื่อมี golden set → **นี่คือเหตุผลที่ขอให้องค์กรช่วยแยกอีเมล 150–200 ฉบับ**
> (ดู [ANALYSIS_enterprise_dataset.md](ANALYSIS_enterprise_dataset.md) ข้อ 4)
>
> ตอนนี้จึงคงน้ำหนักไว้ที่ **30 (ต่ำกว่าเกณฑ์ ยิงเดี่ยวไม่ได้)** — ไม่ลดเพราะ 0% ที่วัดไม่ได้ และไม่เพิ่มเพราะยังไม่มีหลักฐาน

**บทเรียนที่ผมรับไป:** ผมรายงาน "ความแม่น 0%" โดยไม่ได้เช็คก่อนว่าชุดข้อมูลวัดสิ่งนั้นได้จริงไหม — ตัวเลขที่วัดจากชุดที่ไม่มีเงื่อนไขให้วัด ไม่ใช่ "0%" แต่เป็น **"วัดไม่ได้"** ซึ่งคนละความหมายกันเลย (เรื่องเดียวกับที่เราคุยกันเรื่อง `abuseipdb_score` = 0 กับ `= None`)

## 3. ✅ แบรนด์ — เพิ่มตามที่เสนอแล้ว + ทำโดเมนบริษัทให้ตั้งค่าได้

เพิ่มครบตามรายการคุณ: **ttb · ออมสิน (gsb) · ธ.ก.ส. (baac) · AIS · True · dtac · การประปา · ประกันสังคม (sso)**
(Shopee / Lazada / การไฟฟ้า มีอยู่แล้ว) — รวมตอนนี้ ~50 แบรนด์ พร้อมชื่อภาษาไทยคู่กับอังกฤษ

### 🔴 ข้อที่คุณชี้ว่าสำคัญที่สุด — โดเมนบริษัทเอง

> *"BEC ที่อันตรายที่สุดคือปลอมเป็นคนในองค์กรเอง ไม่ใช่ปลอมเป็นแบรนด์ภายนอก"*

**เห็นด้วยเต็มที่ และของเดิมมีช่องโหว่จริง** — เดิมกันได้เฉพาะโดเมนที่โผล่ใน `recipient` ของ request นั้น ซึ่งพลาดเมื่อ: ส่งหาบริษัทลูกคนละโดเมน · `recipient` เป็น alias/distribution list · header ไม่ครบ

ตอนนี้ตั้งใน `.env` ได้:
```bash
PROTECTED_DOMAINS=sammitr.com,sammitr.co.th
```
โดเมนในนี้จะถูกคุ้มครองทั้ง **lookalike** (`sammltr.com`, `sammitr-hr.com`) และ **impersonates_recipient_org** ทุกฉบับ ไม่ต้องพึ่ง header

**ขอโดเมนทั้งหมดของบริษัท (รวมบริษัทลูก/แบรนด์ย่อย) ด้วยครับ** — ตอน deploy จะได้ใส่ให้ครบ

> รอรายชื่อแบรนด์จาก quarantine ของ PMG/Mailcow อยู่ครับ 👍 **เพิ่มทีหลังได้ทันที ไม่ต้องเทรนโมเดลใหม่**
