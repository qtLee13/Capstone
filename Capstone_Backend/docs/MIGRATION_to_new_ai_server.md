---

## สรุปสั้น

AI Server ย้ายจาก VM เดิม (`10.22.1.94` / `192.168.56.101`) ไปเครื่องใหม่ที่พี่ thesis เตรียมให้

**ทุกทีมต้องแก้ 2 อย่างเท่านั้น: `base URL` + `token`** — ชื่อ endpoint, request, response **เหมือนเดิมทุกตัว ไม่มีอะไรเปลี่ยน**

## 1. ทำไมย้ายง่าย — AI เป็น "ปลายทาง" ไม่ได้เรียกใคร

ตรวจโค้ดแล้ว AI Server:
- ❌ **ไม่ได้เรียกเครื่องของทีมไหนเลย** (ไม่มี IP `10.22.1.x` ผูกไว้ในโค้ดสักที่)
- ✅ ยิงออกแค่ VirusTotal / AbuseIPDB / IPQualityScore (ผ่าน internet)
- ✅ มีแต่คนอื่นเรียกเข้ามา

**เพราะฉะนั้นการย้าย = เปลี่ยนที่อยู่อย่างเดียว ไม่มี logic อะไรต้องแก้ทั้งฝั่งเราและฝั่งคุณ**

## 3. 🔴 เรื่องเครือข่าย — ขอความเห็นด่วน

เครื่องใหม่อยู่บน **internet สาธารณะ** ส่วนพวกเราอยู่บน **ZeroTier** (วงปิด) มี 2 ทาง:

### ทาง ก — ลง ZeroTier บนเครื่องใหม่ ⭐ **เสนออันนี้**
เครื่องใหม่เข้าวง `10.22.1.x` เหมือนเดิม
- ✅ ทุกอย่างทำงานเหมือนเดิม **ทุกทีมแค่เปลี่ยนเลข IP**
- ✅ **ไม่ต้องเปิด port ออก internet เลย** — ปลอดภัยที่สุด
- ✅ ไม่ต้องแก้ firewall ฝั่งใคร

**ต้องการจากคนดูแลวง ZeroTier: `network id` + ช่วย authorize เครื่องใหม่**

### ทาง ข — เปิด port 8000 ออก internet
- ⚠️ ต้อง allowlist IP สาธารณะของแต่ละทีม (ถ้า IP เปลี่ยนบ่อยจะพังบ่อย)
- ⚠️ เปิดช่องให้โลกภายนอกเห็น API เรา

> **เราจะตั้งค่าเริ่มต้นเป็น bind `127.0.0.1`** (คนนอกยิงไม่ได้เลย) จนกว่าจะตกลงกันได้

## 4. 🔑 token เปลี่ยนใหม่ — สำคัญ

**token เดิมที่ใช้กันอยู่ตอนนี้จะเลิกใช้ทั้งหมด**

เหตุผล: ค่านี้**รั่วอยู่ใน GitHub public repo** ตอนอยู่บน ZeroTier ยังพอทน (คนนอกยิงไม่ถึง) แต่**พอเครื่องอยู่บน internet ใครอ่าน GitHub ก็เรียก API เราได้ทันที**

- เครื่องใหม่จะ**สุ่ม token ใหม่ตอนติดตั้ง** และเราจะ**ส่งให้แต่ละทีมเป็นการส่วนตัว** (ไม่ลงแชทกลุ่ม ไม่ใส่ใน git)
- ช่วง 2 สัปดาห์แรกเครื่องใหม่จะ**รับทั้ง token ใหม่และเก่า** (grace mode) → ย้ายไม่พร้อมกันก็ไม่พัง
- หลังทุกทีมย้ายครบ **จะปิดตัวเก่า**

> 🙏 ขอความร่วมมือ: **อย่าเอา token ใส่โค้ดที่ push ขึ้น git** ให้อ่านจาก `.env` เสมอ
> (ฝั่งเราเองก็เพิ่งเผลอ push ไฟล์ทดสอบที่มี token ขึ้นไปแล้วลบออก — พลาดกันได้ทุกคน)
